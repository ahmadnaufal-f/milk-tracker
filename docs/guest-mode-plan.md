## Background

The goal is to add a **"Continue without sign in"** feature to the app. Currently, all users must authenticate via Google Sign-In through Firebase Auth. The new feature allows guest users to use the app without signing in, using Firebase Anonymous Auth under the hood so the existing data flow remains largely unchanged.

---

## Tech Stack

- **Framework**: React
- **Auth**: Firebase Auth (Google Sign-In)
- **Database**: Firebase Firestore
- **Backend**: Firebase Functions
- **Session Persistence**: localStorage (active pumping session)
- **State Management**: React Context (no Zustand/Redux)

### Tasks

1. **Add guest login trigger** on the login/landing screen
   - Add a "Continue without sign in" button alongside the existing Google Sign-In button
   - On click, call `signInAnonymously(auth)` from `firebase/auth`

2. **Update AuthContext** (adjust to match actual context file location/name)

     ```js

       isAnonymous: user?.isAnonymous ?? false,
     }
     ```

3. **Create the Firestore user document** on first anonymous sign-in
   - Write to `users/{uid}` with the following fields:
     ```js
     {
       isAnonymous: true,
       createdAt: serverTimestamp(),
       lastActive: serverTimestamp(),
     }
     ```

## Phase 2: Account Linking

**Objective**: Allow guest users to link their Google account and preserve all their data.

### Tasks

1. **Build a persistent banner component** for guest users
   - Should be non-blocking (not a modal, not a gate)
   - Shown on the dashboard while `isAnonymous === true`
   - CTA: *"Save your data — link your Google account"*

2. **Implement account linking**
   - Use `linkWithPopup(auth.currentUser, new GoogleAuthProvider())`
   - On success, update Firestore:
     ```js
     await updateDoc(doc(db, "users", result.user.uid), {
       isAnonymous: false,
     });
     ```
   - The UID does **not** change after linking — all existing data is automatically preserved

3. **Handle linking errors**
   - `auth/credential-already-in-use` — the Google account already has a separate account; handle merge or notify the user
   - `auth/popup-closed-by-user` — silent fail or soft retry prompt

## Phase 4: Cleanup Cron Job

**Objective**: Delete orphaned Firestore data from anonymous users inactive for 30+ days.

### Tasks

1. **Create a scheduled Firebase Function** (weekly cadence recommended)

   ```js
   import { onSchedule } from "firebase-functions/v2/scheduler";
   import { getFirestore } from "firebase-admin/firestore";
   import { getAuth } from "firebase-admin/auth";

   export const cleanupAnonymousUsers = onSchedule("every week", async () => {
     const db = getFirestore();
     const auth = getAuth();
     const cutoff = Date.now() - 30 * 24 * 60 * 60 * 1000;

     const snapshot = await db
       .collection("users")
       .where("isAnonymous", "==", true)
       .where("lastActive", "<=", new Date(cutoff))
       .get();

     const batch = db.batch();

     for (const doc of snapshot.docs) {
       batch.delete(doc.ref);
       try {
         await auth.deleteUser(doc.id);
       } catch (e) {
         // Auth account may already be auto-deleted after 30 days — safe to ignore
       }
     }

     await batch.commit();
   });
   ```

2. **Adjust subcollection cleanup if needed**
   - If pumping data is stored in subcollections under `users/{uid}`, those need to be deleted recursively before deleting the parent document
   - Firebase does not auto-delete subcollections when a parent document is deleted

3. **Add a Firestore composite index** for the query:
   - Fields: `isAnonymous` (ASC) + `lastActive` (ASC)
